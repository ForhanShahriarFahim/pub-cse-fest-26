# HackerRank ICPC-style problem setting

Every problem lives in `problems/<NN>-<slug>/` (NN = difficulty rank; contest
letters are assigned at the end, since the contest order is shuffled except the two
giveaways). A problem is not "done" until `python3 tools/check.py problems/<NN>-<slug>`
prints ALL CHECKS PASSED. Problems are produced one at a time, and the next one is
started only after the user approves the current one.

## Directory layout per problem

```
problems/NN-slug/
  challenge.md        # copy-paste blocks, one per HackerRank Create Challenge field (see below)
  sol.cpp             # reference solution (intended complexity)
  sol.py              # Python solution: must pass within the Python time limit
  Solution.java       # Java solution; HackerRank requires `public class Solution` (compiled as Java 8)
  sol.c               # C solution (C is an allowed language)
  brute.cpp           # obviously-correct slow solution, used only for small inputs
  wrong_*.cpp         # common mistakes (overflow, O(n^2), off-by-one) that the tests MUST reject
  gen.py              # `python3 gen.py <mode> <seed> [args]` -> one input on stdout;
                      #   mode `small` is used by the stress test
  validator.py        # reads one input from stdin, asserts every constraint and format detail
  sample.txt          # hand-written sample (becomes input00)
  testplan.txt        # one official test per line: `file sample.txt` or `gen <mode> <seed> ...`
  config.json         # time limits used by the checker {"tl_cpp", "tl_py", "tl_java"}
  tests/input/inputNN.txt, tests/output/outputNN.txt
  tests.zip           # what gets uploaded to HackerRank (built by tools/check.py)
  editorial.md        # short solution idea + complexity
  draw_*.py, *.png    # optional illustration (Pillow), drawn FROM sample.txt so it can't drift
```

Images: draw them with a script that reads the sample, so the picture always matches the
data. Look at the PNG before shipping. On HackerRank, upload the PNG in the statement
editor where `![...](file.png)` appears.

## challenge.md format (mirrors HackerRank's Create Challenge form)

Sections in this order, each followed by a `~~~` fenced block holding the exact text
to paste (use ```` ```markdown ```` inside rich fields, `~~~` outside):

1. Challenge Name
2. Description (plain text, at most 140 characters)
3. Problem Statement (story + precise task; define every term; NO samples here,
   because HackerRank renders the samples from the test cases marked Sample)
4. Input Format
5. Constraints (Unicode for math: ≤, 10⁵, ×; no LaTeX or images of formulas)
6. Output Format
7. Tags
8. Test Cases tab: number of cases, which ones are Sample, the explanation text for each sample
9. Settings: languages, limits, binary scoring

Rules: no floating-point output unless a custom checker is set up; exactly one correct
output per input (otherwise a custom checker is required); give a modulus when answers
are huge. Update the problem index table in README.md whenever a problem is added,
renumbered or approved, then run `python3 tools/build_desk.py` and republish
`setter-desk.html` (the copy-paste page the user works from) to the same artifact URL.

## Testing checklist

1. `validator.py` passes on every input file (including samples).
2. `sol.cpp`, `sol.py` and `brute.cpp` agree on ≥ 1000 random small cases (stress test).
3. `sol.cpp` and `sol.py` agree on every official test.
4. Max tests: `sol.cpp` runs well under the C++ limit; `sol.py` well under the Python limit.
5. Every `wrong_*.cpp` fails at least one official test (WA or TLE).
6. Tests include: samples, minimum values, maximum values, all-equal values,
   sorted / reverse-sorted, edge cases specific to the problem, and anti-greedy cases.
7. Output files are generated by `sol.cpp` only, with a trailing newline.

## Packaging for HackerRank

Zip must contain `input/inputNN.txt` and `output/outputNN.txt` (two-digit, zero-based,
matching numbers). Build from inside `tests/`: `cd tests && zip -r ../tests.zip input output`.
In the HackerRank UI: mark input00 (and any other samples) as sample, set binary
(all-or-nothing) scoring so the contest behaves like ICPC, and set the time limit.
